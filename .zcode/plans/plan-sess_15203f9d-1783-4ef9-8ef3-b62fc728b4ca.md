## Custom GST Percentage Management — Implementation Plan

### Goal
Allow admin to manage the list of available GST percentages in Settings (add custom values like 10%, remove unused ones). The CategoryForm dropdown sources from this list dynamically instead of the hardcoded `[5, 12, 18]` constant. Then test end-to-end: create a category with 10%, create a product, create+complete an order, verify the GST report, and clean up.

### Architecture decisions (confirmed with user)
- **Default slabs** on first open: `0, 5, 12, 18, 28` (Indian standard).
- **Orphan handling**: if a category's existing rate isn't in the configured list, the dropdown shows it (marked) plus the current list — never silently overwrite.
- **Storage**: store the slab list as a JSON-stringified array in the existing `settings` table under a new key `gst_slabs`. Max value well under the 5000-char cap.
- **Reports**: no change needed — already auto-creates buckets for any slab value.

---

### Step 1 — Domain: add `GST_SLABS` setting key + helper
- `apps/admin/domain/types/settings.ts` — add `GST_SLABS = 'gst_slabs'` to the `SettingKey` enum.
- `apps/admin/domain/schemas/settings.schema.ts` — add `'gst_slabs'` to the `z.enum([...])` of valid keys.
- `apps/admin/domain/types/category.ts` — export `DEFAULT_GST_SLABS = [0, 5, 12, 18, 28]`; update the `GST_OPTIONS` fallback to match.

### Step 2 — Service: JSON parse/serialize for the slab list
- `apps/admin/services/settingsService.ts` — add `getGstSlabs()` (reads setting, `JSON.parse`, returns `DEFAULT_GST_SLABS` on missing/corrupt) and `setGstSlabs(slabs)` (validates: unique, 0–100 integers, sorted ascending, non-empty; `JSON.stringify` + save).

### Step 3 — Hooks: React Query wrappers
- `apps/admin/hooks/useSettings.ts` — `useGstSlabs()` query + `useUpdateGstSlabs()` mutation (invalidates `gstSlabs` + `categories`).
- `apps/admin/lib/query-client.ts` — add `gstSlabs: ['settings', 'gstSlabs']` to `queryKeys`.

### Step 4 — Settings UI: GST slabs manager card
- `apps/admin/app/dashboard/settings/page.tsx` — inside the existing "GST Configuration" card, after the toggle (visible only when `isGstEnabled`): chip list with ✕ to remove, input + "Add" button (numeric 0–100, integer, reject duplicates), Save button, dynamic copy. Admin/Manager only.

### Step 5 — CategoryForm: dynamic dropdown
- `apps/admin/components/admin/CategoryForm.tsx` — replace hardcoded `GST_OPTIONS.map(...)` with fetched slabs from `useGstSlabs()`. If the category's current rate isn't in the list, prepend it (marked "current") so the value is never silently lost. Fall back to `DEFAULT_GST_SLABS` while loading.

### Step 6 — Verification (mandatory per AGENTS.md)
- `tsc --noEmit` in `apps/admin`. Fix all errors.

### Step 7 — End-to-end test (live, against DB)
1. Add 10% slab via Settings UI → confirm it persists.
2. Create dummy category "QA Test — GST 10%" with `gst_percentage: 10`.
3. Create dummy product "QA Test Product" under it, price ₹1000/day, with stock.
4. Create order with that product, 1 day, GST enabled → verify `order_items.gst_percentage = 10` and the GST math (base 909.09, gst 90.91).
5. Start rental → Process return → verify `completed`.
6. Open GST report → confirm 10% slab appears in summary + detail rows.
7. Cleanup in safe order: order → product → category → remove 10% slab. Verify each deletion.
8. Report any issues and how I solved them.

### Rollback safety
- Missing/corrupt `gst_slabs` setting → every consumer falls back to `DEFAULT_GST_SLABS`.
- Removing a slab from Settings does NOT retroactively change existing categories — only affects the dropdown for future edits.
- End-to-end test cleans up after itself.
